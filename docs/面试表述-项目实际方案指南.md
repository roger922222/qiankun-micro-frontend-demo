## 🔧 技术方案表述（2分钟）

### 1. 核心架构（分层表述）
```
"我的方案采用分层设计：

**第一层：认证管理层**
- AuthManager负责Cookie操作（同域场景）
- AuthBridge负责Token同步（跨域场景）
- 统一的事件总线协调各模块通信

**第二层：权限控制层**  
- AuthMiddleware提供权限验证API
- TokenSecurity负责Token加解密
- CSRFProtection防止跨站请求伪造

**第三层：应用集成层**
- React Hook：useAuth提供认证状态管理
- Vue Composable：同功能的Vue版本
- 自动Token刷新和错误处理机制"
```

### 2. 关键技术实现（问题导向）
> "技术实现上，我重点解决了三个核心问题：

**同域Cookie共享**：通过设置`.example.com`域名的Cookie，实现主应用和子应用间的登录态共享。使用`HttpOnly`、`Secure`、`SameSite`等属性确保安全。

**跨域Token同步**：由于localStorage遵循同源策略，我通过`BroadcastChannel`+`storage`事件实现跨标签页同步，通过自定义事件实现应用内通信。

**状态实时性**：当用户在一个应用登录/登出时，通过事件广播机制，所有打开的应用都能立即感知状态变化，无需刷新页面。"

### 3. 核心代码展示（关键片段）
```typescript
"// 1. Cookie管理（同域方案）
export class AuthManager {
  static setCookie(name: string, value: string, options: { expires?: Date; domain?: string } = {}): void {
    const parts = [`${name}=${encoded}`, 'path=/'];
    if (domain) parts.push(`domain=${domain}`); // .example.com
    if (process.env.NODE_ENV === 'production') {
      parts.push('SameSite=None'); // 跨域场景
      parts.push('Secure');
    }
  }
}

// 2. Token桥接（跨域方案）
export class AuthBridge {
  private handleLogin = (event: Event) => {
    const { detail } = event as CustomEvent<{ token: string; refreshToken?: string }>;
    this.token = detail?.token || null;
    this.persist({ token: this.token, timestamp: Date.now() }); // localStorage同步
    this.notifySubscribers(); // 通知所有订阅者
  };
}

// 3. 应用集成Hook
export function useAuth(appId: string): UseAuthReturn {
  useEffect(() => {
    const unsubscribe = authBridge.subscribe(appId, (newToken) => {
      setToken(newToken); // 自动同步Token状态
      setLoading(false);
    });
    return () => unsubscribe();
  }, [appId]);
}"
```

## 💡 面试Q&A准备

### Q1: "为什么选择Cookie+Token的混合方案？"

**回答要点**：
- 同域场景：Cookie方案简单可靠，服务端可直接读取
- 跨域场景：Token方案灵活，不受同源策略限制
- 渐进增强：从同域到跨域可以平滑迁移
- 兼容性：支持各种部署环境和浏览器版本

### Q2: "如何保证Token同步的实时性？"

**回答要点**：
- 事件驱动：使用CustomEvent实现应用内即时通知
- 存储监听：通过storage事件实现跨标签页同步
- 广播通道：BroadcastChannel支持同源多页面通信
- 无轮询：避免性能开销，实现真正的实时同步

### Q3: "安全性是如何保障的？"

**回答要点**：
- 传输安全：HTTPS + Secure Cookie属性
- 存储安全：Token加密存储，防止XSS攻击
- 请求安全：CSRF Token验证机制
- 权限控制：细粒度的权限验证中间件
- 过期机制：自动Token刷新和失效处理

### Q4: "如何处理浏览器兼容性问题？"

**回答要点**：
- 渐进增强：BroadcastChannel不可用时的降级方案
- Polyfill支持：核心功能不依赖新API
- 开发环境：支持localhost等开发场景
- 错误处理：完善的异常捕获和恢复机制
