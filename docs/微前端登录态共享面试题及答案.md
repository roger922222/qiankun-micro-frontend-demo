# 微前端登录态共享面试题及答案

## 基础问题

### 1. 微前端中如何实现登录态共享？

**问题描述**：在微前端架构下，主应用和多个子应用如何共享用户的登录状态？

**参考答案**：

微前端登录态共享主要有以下几种方案：

1. **同域Cookie共享方案**
   - 所有应用部署在同一顶级域名下（如 *.example.com）
   - 设置Cookie的domain属性为顶级域名
   - 通过Cookie自动传递登录态
   - 优点：实现简单，浏览器自动处理
   - 缺点：受限于域名，存在CSRF风险

2. **跨域Token共享方案**
   - 使用localStorage/sessionStorage存储Token
   - 通过postMessage或自定义事件同步Token
   - 子应用监听主应用的登录状态变化
   - 优点：不受域名限制，安全性较高
   - 缺点：实现复杂，需要手动同步

3. **统一认证中心方案**
   - 独立的认证服务处理登录逻辑
   - 所有应用通过OAuth2.0/OpenID Connect协议接入
   - 使用SSO（单点登录）机制
   - 优点：标准化，安全性高，支持第三方登录
   - 缺点：架构复杂，需要额外的认证服务

**最佳实践**：我们通常结合使用Cookie和Token方案，同域情况下优先使用Cookie，跨域情况下使用Token共享，并配合统一的事件总线进行状态同步。

### 2. 如何处理Token的自动续期？

**问题描述**：在微前端应用中，如何实现Token的无感刷新，避免用户频繁登录？

**参考答案**：

Token自动续期的实现方案：

```typescript
class TokenRefresher {
  private refreshTimeout: NodeJS.Timeout | null = null;
  private readonly refreshThreshold = 5 * 60 * 1000; // 提前5分钟

  startTokenRefresh(token: string): void {
    const expiresIn = this.getTokenExpiresIn(token);
    const refreshTime = Math.max(0, expiresIn - this.refreshThreshold);
    
    this.refreshTimeout = setTimeout(() => {
      this.refreshToken();
    }, refreshTime);
  }

  private async refreshToken(): Promise<void> {
    try {
      const refreshToken = localStorage.getItem('refresh_token');
      const response = await fetch('/api/auth/refresh', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ refreshToken })
      });

      if (response.ok) {
        const { token, refreshToken: newRefreshToken } = await response.json();
        // 更新Token并重新启动定时器
        this.updateTokens(token, newRefreshToken);
        this.startTokenRefresh(token);
      }
    } catch (error) {
      // 刷新失败，跳转到登录页
      this.redirectToLogin();
    }
  }
}
```

关键点：
- 在Token即将过期前自动刷新
- 使用refresh_token获取新的access_token
- 刷新失败时要有降级处理
- 避免并发刷新请求

### 3. 如何处理跨域情况下的Cookie？

**问题描述**：当主应用和子应用部署在不同域名下时，如何处理Cookie的跨域问题？

**参考答案**：

跨域Cookie处理方案：

1. **CORS配置**
   ```javascript
   // 后端配置
   app.use(cors({
     origin: ['https://main.example.com', 'https://app1.example.com'],
     credentials: true, // 允许携带Cookie
     allowedHeaders: ['Content-Type', 'Authorization']
   }));
   ```

2. **前端请求配置**
   ```javascript
   fetch('/api/data', {
     method: 'GET',
     credentials: 'include', // 携带Cookie
     headers: {
       'Content-Type': 'application/json'
     }
   });
   ```

3. **代理方案**
   - 使用Nginx反向代理，将不同域名的请求代理到同一域名
   - 子应用通过主应用的API网关访问后端服务

4. **Token替代方案**
   - 跨域情况下优先使用Token认证
   - 将Token存储在localStorage中
   - 通过Authorization头传递Token

注意事项：
- 需要配置CORS允许跨域请求
- 设置withCredentials/credentials为true
- 考虑安全性，避免CSRF攻击
- 生产环境使用HTTPS

### 4. 如何实现单点登录（SSO）？

**问题描述**：设计一个微前端架构下的单点登录系统，用户只需要登录一次就可以访问所有子应用。

**参考答案**：

SSO实现方案：

```typescript
// 统一认证中心
class SSOAuthCenter {
  private sessions = new Map<string, SSOSession>();

  // 用户登录
  async login(credentials: LoginCredentials): Promise<SSOTicket> {
    const user = await this.validateUser(credentials);
    const session = this.createSession(user);
    const ticket = this.createTicket(session);
    
    return ticket;
  }

  // 验证Ticket
  async validateTicket(ticket: string, service: string): Promise<AuthResult> {
    const session = this.sessions.get(ticket);
    
    if (!session || this.isTicketExpired(session)) {
      throw new Error('Invalid ticket');
    }

    // 记录服务访问
    session.services.add(service);
    
    return {
      token: session.token,
      user: session.user,
      permissions: session.permissions
    };
  }

  // 全局登出
  async globalLogout(ticket: string): Promise<void> {
    const session = this.sessions.get(ticket);
    
    if (session) {
      // 通知所有已访问的服务登出
      for (const service of session.services) {
        await this.notifyServiceLogout(service, ticket);
      }
      
      this.sessions.delete(ticket);
    }
  }
}

// 子应用集成
class SSOClient {
  private authCenterUrl = 'https://auth.example.com';

  async authenticate(): Promise<void> {
    const ticket = this.getTicketFromURL();
    
    if (ticket) {
      // 验证Ticket
      const result = await this.validateTicket(ticket);
      this.setLocalAuth(result);
    } else {
      // 重定向到认证中心
      this.redirectToAuthCenter();
    }
  }

  private redirectToAuthCenter(): void {
    const service = encodeURIComponent(window.location.href);
    const redirectUrl = `${this.authCenterUrl}/login?service=${service}`;
    window.location.href = redirectUrl;
  }
}
```

实现要点：
- 独立的认证中心处理所有登录请求
- 使用Ticket机制验证用户身份
- 支持全局登出功能
- 各应用通过OAuth2.0协议接入

```typescript
class AuthStatusPoller {
```

### 6. 如何防止登录态被盗用？

   ```typescript
   class TokenSecurity {
     // 使用Web Crypto API加密
     async encryptToken(token: string): Promise<string> {
       const key = await crypto.subtle.generateKey(
         { name: 'AES-GCM', length: 256 },
         true,
         ['encrypt', 'decrypt']
       );
       
       const encoded = new TextEncoder().encode(token);
       const iv = crypto.getRandomValues(new Uint8Array(12));
       
       const encrypted = await crypto.subtle.encrypt(
         { name: 'AES-GCM', iv },
         key,
         encoded
       );
       
       return {
         encrypted: Array.from(new Uint8Array(encrypted)),
         iv: Array.from(iv),
         key: await crypto.subtle.exportKey('jwk', key)
       };
     }
   }
   ```

```typescript
class TokenCacheManager {
  private l1Cache: Map<string, CacheEntry>; // 内存缓存
  private l2Cache: Redis; // Redis缓存
  private l3Storage: Database; // 数据库存储

  async getToken(key: string): Promise<string | null> {
    // L1缓存
    const l1Entry = this.l1Cache.get(key);
    if (l1Entry && !this.isExpired(l1Entry)) {
      return l1Entry.value;
    }
    
    // L2缓存
    const l2Entry = await this.l2Cache.get(key);
    if (l2Entry) {
      this.l1Cache.set(key, l2Entry);
      return l2Entry.value;
    }
    
    // L3存储
    const l3Entry = await this.l3Storage.get(key);
    if (l3Entry) {

      this.l1Cache.set(key, l3Entry);
      return l3Entry.value;
    }
    
    return null;
  }
}

// 3. 熔断降级
class CircuitBreaker {
  private failures = 0;
  private timeout = 60000; // 60秒
  private threshold = 5; // 失败阈值
  private state: 'closed' | 'open' | 'half-open' = 'closed';

  async execute<T>(operation: () => Promise<T>): Promise<T> {
    if (this.state === 'open') {
      throw new Error('Circuit breaker is open');
    }
    
    try {
      const result = await operation();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  private onFailure(): void {
    this.failures++;
    
    if (this.failures >= this.threshold) {
      this.state = 'open';
      setTimeout(() => {
        this.state = 'half-open';
      }, this.timeout);
    }
  }

  private onSuccess(): void {
    this.failures = 0;
    this.state = 'closed';
  }
}
```

- 熔断降级，防止雪崩效应

```typescript
// 1. 连接池优化
class ConnectionPool {
  private pool: Connection[] = [];
  private maxConnections = 100;
  private minConnections = 10;

  async getConnection(): Promise<Connection> {
    if (this.pool.length > 0) {
      return this.pool.pop()!;
    }
    
    if (this.pool.length < this.maxConnections) {
      return this.createConnection();
    }

// 2. 异步处理
class AsyncAuthProcessor {
  private queue: Queue<AuthRequest>;
  private workers: Worker[] = [];

  constructor(workerCount = 4) {
    this.queue = new Queue();
    this.initializeWorkers(workerCount);
  }

  private initializeWorkers(count: number): void {
    for (let i = 0; i < count; i++) {
      const worker = new Worker('./auth-worker.js');
      worker.onmessage = this.handleWorkerMessage.bind(this);
      this.workers.push(worker);
    }

  async processAuth(request: AuthRequest): Promise<AuthResult> {
    return new Promise((resolve, reject) => {
      const job = {
        request,
        resolve,
        reject
      };
      
      this.queue.enqueue(job);
      this.assignWork();
    });
  }
}

// 3. 批处理优化
class BatchTokenValidator {
  private batchQueue: TokenValidationRequest[] = [];
  private batchTimeout: NodeJS.Timeout | null = null;
  private batchSize = 100;
  private batchDelay = 50; // 50ms

  async validateToken(token: string): Promise<ValidationResult> {
    return new Promise((resolve, reject) => {
      this.batchQueue.push({
        token,
        resolve,
        reject,
        timestamp: Date.now()
      });
      
      this.scheduleBatchProcessing();
    });
  }

  private scheduleBatchProcessing(): void {
    if (this.batchTimeout) {
      clearTimeout(this.batchTimeout);
    }
    
    if (this.batchQueue.length >= this.batchSize) {
      this.processBatch();
    } else {
      this.batchTimeout = setTimeout(() => {
        this.processBatch();
      }, this.batchDelay);
    }
  }

  private async processBatch(): Promise<void> {
    const batch = this.batchQueue.splice(0, this.batchSize);
    
    if (batch.length === 0) return;
    
    try {
      // 批量验证
      const results = await this.batchValidate(batch.map(item => item.token));
      
      // 分发结果
      batch.forEach((request, index) => {
        request.resolve(results[index]);
      });
    } catch (error) {
      // 批量失败，逐个重试
      batch.forEach(request => {
        this.validateTokenIndividual(request.token)
          .then(request.resolve)
          .catch(request.reject);
      });
    }
  }
}
```

优化策略：
- 连接池复用，减少连接创建开销
- 异步处理，提高并发能力
- 批处理操作，减少网络往返
- 缓存热点数据，降低后端压力
- 读写分离，提高查询性能
- CDN加速，就近服务用户

```typescript
class HealthChecker {
  private checks: HealthCheck[] = [
    new DatabaseHealthCheck(),
    new RedisHealthCheck(),
    new ExternalServiceHealthCheck(),
    new CertificateHealthCheck()
  ];

  async checkHealth(): Promise<HealthStatus> {
    const results = await Promise.allSettled(
      this.checks.map(check => check.execute())
    );
    
    const status: HealthStatus = {
      status: 'healthy',
      checks: {},
      timestamp: Date.now()
    };
    
    results.forEach((result, index) => {
      const check = this.checks[index];
      
      if (result.status === 'fulfilled') {
        status.checks[check.name] = result.value;
        if (result.value.status !== 'healthy') {
          status.status = 'degraded';
        }
      } else {
        status.checks[check.name] = {
          status: 'unhealthy',
          error: result.reason.message
        };
        status.status = 'unhealthy';
      }
    });
    
    return status;
  }
}

class AlertManager {
  private rules: AlertRule[] = [
    {
      name: 'High Login Failure Rate',
      condition: (metrics: AuthMetrics) => {
        const failureRate = metrics.loginFailures / metrics.loginAttempts;
        return failureRate > 0.1; // 10%失败率
      },
      severity: 'warning',
      channels: ['email', 'slack']
    },
    {
      name: 'Token Validation Latency High',
      condition: (metrics: AuthMetrics) => {
        const p99Latency = metrics.tokenValidationLatency.getP99();
        return p99Latency > 1000; // 1秒
      },
      severity: 'critical',
      channels: ['email', 'slack', 'pagerduty']
    },
    {
      name: 'System Unhealthy',
      condition: async () => {
        const health = await this.healthChecker.checkHealth();
        return health.status === 'unhealthy';
      },
      severity: 'critical',
      channels: ['email', 'slack', 'pagerduty', 'sms']
    }
  ];

  async evaluateRules(metrics: AuthMetrics): Promise<Alert[]> {
    const alerts: Alert[] = [];
    
    for (const rule of this.rules) {
      try {
        const triggered = await rule.condition(metrics);
        
        if (triggered) {
          alerts.push({
            rule: rule.name,
            severity: rule.severity,
            timestamp: Date.now(),
            message: `Alert ${rule.name} triggered`,
            channels: rule.channels
          });
        }
      } catch (error) {
        console.error(`Error evaluating rule ${rule.name}:`, error);
      }
    }
    
    return alerts;
  }
}
```

### 11. 零信任架构下如何设计细粒度授权？

**问题描述**：在零信任背景下，微前端认证系统如何实现最小权限和细粒度授权管理？

**参考答案**：

- 将身份验证、设备信任、上下文信息纳入`Policy Decision Point (PDP)`，采用ABAC/OPA等策略引擎。
- Token中仅携带短期Scope，具体权限由后端动态签发`Policy`。
- 在子应用侧实现`usePermission`钩子，实时向PDP请求`permit/deny`，并缓存带过期时间的授权结果。
- 对敏感操作执行多因素验证（MFA）+ 风险评分，结合IP、设备指纹、行为模型动态调整权限。
- 通过`Policy Enforcement Point (PEP)`在API网关、前端路由、组件层分层校验。

```typescript

  constructor(private opaClient: OpaClient) {}

// sub-apps/react-app/src/hooks/usePermission.ts
export function usePermission(action: string) {
  const [allowed, setAllowed] = useState(false);

  useEffect(() => {
    const controller = new AbortController();

    fetch('/api/authz/decision', {
      method: 'POST',
      body: JSON.stringify({ action }),
      headers: { 'Content-Type': 'application/json' },
      signal: controller.signal
    })
      .then(res => res.json())
      .then(result => setAllowed(result.allow === true));

    return () => controller.abort();
  }, [action]);

  return allowed;
}
```

### 12. 如何设计登录态风险控制与告警指标？

**问题描述**：为了及时发现登录异常，需要构建哪些风控策略和指标体系？

**参考答案**：

- 指标体系：登录失败率（分地域/设备）、刷新Token失败率、同账号异地登录次数、登录延迟P95/P99、可疑IP命中率、异常行为告警数等。
- 策略：设备指纹比对、IP信誉库校验、同IP高频尝试限流、深夜异常登录即时短信/机器人告警。
- 实践：结合`AuthMonitor`上报，将指标推送到Prometheus + Grafana，配置`High Login Failure Rate`、`Abnormal Location`等告警规则。
- 落地：通过`RiskEngine`拦截高风险请求，触发验证码、短信验证或临时封禁。

```typescript
// monitoring/risk-metrics.ts
export class RiskMetricsCollector {
  private metrics = {
    loginFailures: new Counter('login_failures'),
    refreshFailures: new Counter('refresh_failures'),
    suspiciousLogins: new Counter('suspicious_logins')
  };

  recordLoginAttempt(result: LoginResult) {
    if (!result.success) {
      this.metrics.loginFailures.inc({ region: result.region, device: result.device });
    }

    if (result.flags.includes('ABNORMAL_LOCATION')) {
      this.metrics.suspiciousLogins.inc({ userId: result.userId });
    }
  }
}

// services/risk-engine.ts
export class RiskEngine {
  evaluate(context: LoginContext): RiskDecision {
    const factors = [
      this.ipReputation(context.ip),
      this.deviceTrust(context.deviceFingerprint),
      this.locationChange(context.location)
    ];

    const score = factors.reduce((acc, value) => acc + value.score, 0);
    if (score > 80) {
      return { action: 'BLOCK', reason: factors.map(f => f.reason) };
    }
    if (score > 50) {
      return { action: 'CHALLENGE', challenge: 'MFA' };
    }
    return { action: 'ALLOW' };
  }
}
```

### 13. 登录事件顺序与并发冲突如何处理？

**问题描述**：用户快速切换账号或多窗口并发登录时，如何保证状态一致性？

**参考答案**：

- 在`AuthBridge`中维护`loginVersion`，每次登录递增，登出只清理当前版本。
- 通过`RequestDeduplication`对刷新接口做去重，防止并发刷新导致旧Token覆盖新Token。
- 利用`BroadcastChannel`广播`auth:login`事件时附带`version`，子应用仅在`version`更新时响应。
- 统一引入`LoginQueue`（基于Promise队列）确保同一用户的登录流程串行执行。
- 落地测试：编写端到端脚本模拟多窗口/多账号切换，校验最终登录态正确性。

```typescript
// shared/utils/login-queue.ts
export class LoginQueue {
  private queue = new Map<string, Promise<any>>();

  enqueue(userId: string, task: () => Promise<void>) {
    const current = this.queue.get(userId) || Promise.resolve();

    const next = current.then(() => task()).finally(() => {
      if (this.queue.get(userId) === next) {
        this.queue.delete(userId);
      }
    });

    this.queue.set(userId, next);
    return next;
  }
}

// shared/communication/auth-bridge.ts (节选)
private loginVersion = 0;

private handleLogin(event: CustomEvent) {
  const version = ++this.loginVersion;
  this.token = event.detail.token;
  this.notifySubscribers({ token: this.token, version });
  this.broadcast?.('auth:login', { token: this.token, version });
}

private handleBroadcast(event: MessageEvent) {
  if (event.data?.type === 'auth:login') {
    const { token, version } = event.data.payload;
    if (version > this.loginVersion) {
      this.loginVersion = version;
      this.token = token;
      this.notifySubscribers({ token });
    }
  }
}
```

### 14. 如何实现统一登出与多终端会话治理？

**问题描述**：用户在一个终端登出后，如何保证所有终端同步退出，并支持运营侧强制下线？

**参考答案**：

- 认证中心维护`SessionIndex`映射（用户ID -> 终端实例列表），登出时批量吊销对应`refresh_token`。
- 每个终端通过WebSocket/SSE订阅`logout`事件，收到后执行`AuthBridge.clearToken()`并跳转登录页。
- 引入`SessionHeartbeat`，终端定期上报活动状态，若`heartbeat`超时则自动失效会话。
- 管理后台提供`强制下线`接口，触发踢下线并记录审计日志。
- 对企业账号支持设定最大并发会话数，超过阈值时优先删除最久未使用的会话。
